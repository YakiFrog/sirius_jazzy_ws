# LauncherのNav2 Lifecycle画面

左メニューの **Lifecycle** から開きます。約2秒ごとに状態を更新します。
地図配信・AMCL・グローバル／ローカルコストマップ・経路計画・速度制御など13ノードを対象とします。
起動していないオプションのノードも「未取得」として表示します。

上段の「自律移動のつながり」は、地図・経路と速度指令の代表的な処理の流れを示します。
グローバル／ローカルコストマップは、ライフサイクル状態と実際のコストマップ受信を別に表示します。
TFは`map`からロボットまでの接続、スキャンはAMCLの使用トピック、`twist_mux`は接続・停止ロック、
駆動はドライバー応答と停止状態を示します。これは全センサーや走行可能性の保証ではありません。
矢印は処理・依存関係の概略で、DDS配信接続をすべて描いたものではありません。
線のアニメーションは流れのイメージであり、通信の有無や正常性を示すものではありません。
画面幅が狭い場合は図を横スクロールできます。動きを減らす設定にも対応します。
図のノードを選ぶと、そのノードの詳細と操作を開けます。TF・スキャン・mux・駆動はそれぞれ
既存のTF Tree、Topics、走行診断画面を開きます。図を選ぶだけで制御コマンドは送信しません。

## 状態と操作

| 現在状態 | 実行可能な操作 | 到達状態 |
|---|---|---|
| 未設定（unconfigured） | 設定 | 待機（inactive） |
| 待機（inactive） | 有効化 | 稼働（active） |
| 稼働（active） | 無効化 | 待機（inactive） |
| 待機（inactive） | 設定解除 | 未設定（unconfigured） |

画面を開く・更新するだけでは状態を変更しません。対象ボタンの確認後に一度だけ要求します。
送信前に実機の現在状態と許可された遷移を再確認し、変わっていれば拒否します。
停止解除・ゴール送信・パラメーター変更は行いません。
ただし有効化によって既存ゴールの走行が再開したり、Nav2の管理により関連ノードへ影響する場合があります。

## コストマップが出ないとき

`active`とコストマップ受信は別々に表示します。
「有効化中」や直近のTF待ち通知がある場合は、TFTreeとInitialPoseの設定を確認します。
グローバルコストマップは通常`planner_server`（経路計画）、ローカルコストマップは
`controller_server`（速度制御）の有効化に連動します。親ノードの状態も確認してください。
依存ノードを自動で操作する機能ではありません。

## 履歴・応答待ち

監視開始後の状態変化を最大60件、現在のWebサーバーでの操作を最大20件表示します。
遷移イベントとGetStateの両方を監視し、未受信・古い状態では操作を無効にします。
過去の履歴はサーバー／受信プロセスの再起動で消えるため、以前の失敗はログも確認してください。
TF待ちを含むサービス呼び出しは時間がかかります。通信エラーや期限超過でも要求が
実機で継続している可能性があるため、自動再送せず状態を更新してください。

APIは認証済みの`GET /api/lifecycle`と明示的な`POST /api/lifecycle/transition`です。
状態監視は`navigation_monitor.py`、操作は`lifecycle_service.py`と単発の`lifecycle_worker.py`に分離しています。
