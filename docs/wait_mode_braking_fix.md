# 待機優先の停止反復対策（2026-10-23）

## 変更

- RPPのWaitPathだけ、衝突予測時はゼロ速度で待機する。進路を実際の候補速度で毎周期確認し、連続1秒クリアした後に復帰する。BTの再試行や新しいゴールでも待機状態を引き継ぐ。判定が中断された時間はクリア時間に数えない。
- Collision MonitorのSTOP/APPROACHも待機・再発進制限へ反映する。Collision Monitor自体の保護、衝突範囲、判定時間、低電圧の閾値は維持する。
- WaitPathの並進加速上限は0.3 m/s²。曲率を保つよう角速度も同率で調整する。減速・緊急停止は遅延させない。通常のMPPIは変更しない。
- wait_normal / wait_activeのRPP角加速度1.0、キャンセル減速度0.6を明示する。
- Roboteqの電圧・フォルト保護が働くと電子停止を保持する。電源復帰だけでは再発進しない。電圧・フォルト・受信状態が正常なときに、Webから電子緊急停止を明示解除する。正常化前の解除は拒否する。
- モータードライバー起動時も電子停止ON。低電圧の原因自体（電源・配線・負荷）は未確定であり、今回の処置は停止・復帰の反復防止である。PIDゲイン・積分上限は変更しない。

## 検証

- Desktop/NUCのビルド成功。
- 実RPP＋模擬コストマップ：障害物の出入り、クリア待機、Collision Monitor通知、緊急停止、キャンセルの2件成功（両ホスト）。既存RPP26件もDesktopで成功。
- 実Roboteqドライバー＋模擬シリアル：起動時停止、低電圧保持、電圧復帰時の自動再発進ゼロ、不健康時の解除拒否、正常化後の手動解除が成功（両ホスト）。
- NUCで短い直進：指令0.08m/sを0.8秒。車輪オドメトリ約2.6cm、最大計測速度約0.041m/s、駆動電圧13.0〜13.3V、走行中フォルト0。終了後は電子停止ON。
- 構成・ルーティングのPythonテストは18成功、既存fastモードの予測距離7.2mが旧テスト上限5.5mを超える1件が失敗。今回変更した待機・保護の機能とは独立した既存不整合。
- graphify updateは大規模ツリーのため2秒で打ち切り、更新完了は未確認。
