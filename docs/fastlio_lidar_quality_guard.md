# FAST-LIO LiDAR quality guard

Siriusの実機設定で `lidar_quality.enabled: true` を指定する。汎用FAST-LIOノードの既定値はfalse。
生点群 `/velodyne_points` と既存の取り付け補正、全16リングの間引き、車輪融合設定は維持する。

## 動作

各スキャンの反復更新に入る時の対応点を評価する。同じスキャン内の反復で回復カウントは増やさない。

|条件|LiDAR情報の重み|内部地図への点の追加|
|---|---:|---|
|対応点・対応率・残差・法線の方向分布が良好|1.0|有効|
|法線方向が偏る、対応率や残差が弱い|0.2|停止|
|対応点30未満、対応率0.1未満、平均残差0.15m超、非有限値|0|停止|
|良好に戻ってから10スキャン連続確認中|0.2|停止|

法線情報行列の最小/最大固有値比0.003未満を方向の偏りとする。
補正位置0.5mまたは補正角0.15radを超える更新は、状態と共分散を予測値に戻し、
新鮮な車輪情報があれば車輪観測のみで更新し直す。車輪情報がなければIMU予測を維持する。
復帰判定はスキャン数によるため、10Hzでは約1秒、20Hzでは約0.5秒の連続確認になる。

地図追加停止はFAST-LIO内部のikd-Treeと、表示・保存用 `/Laser_map` の蓄積の両方に適用する。
既存地図の表示は続ける。現在のColored3DMapは `/Laser_map` の形状を使うため、こちらにも反映される。
外部で `/cloud_registered` や `/cloud_registered_body` を独自に蓄積する処理には、
この地図追加停止は伝わらない。その場合は診断の `map_update_allowed` も参照する必要がある。
空に近いスキャンは初期化後であれば車輪更新を継続できるが、LiDARメッセージ自体が途絶した場合の
独立したIMU/車輪周期のTF配信は追加していない。

## 車輪融合と既存EKFの関係

標準FAST-LIOへのこのワークスペースの追加機能。`/odom` のchild frameで表された
vx/vy/vzとyaw角速度をFAST-LIOの誤差状態フィルタの観測に加える。生オドメトリの絶対位置・原点は使わない。
既定の車輪値vy/vz=0は車体座標系の速度拘束になるが、地図座標のZを0に固定する処理ではない。

`sf_real` のrobot_localization EKFは別の推定器であり、同じ結果・実績を保証しない。
この機能は外部EKFへの自動切替ではない。`/odom/filtered` をそのまま入力すると、共有IMU情報の
二重利用などを考慮する必要があるため、今回の変更では行わない。
外部EKFと比較併用する場合も同じ車体TFの二重配信を避ける必要がある。

## 診断と限界

`/fastlio/diagnostics` JSONの `lidar_health` にmode、reason、LiDAR重み、地図追加可否、
対応点数・対応率・残差・固有値比・補正量・回復カウント・車輪情報の有効性を出す。
`map_updates_frozen` と `estimator_state.map_points_added` で実際の追加停止も確認できる。
record_3dmap/record_loc3dはこの診断を保存し、実行時の閾値もcaptureに保存する。

幾何・残差による保護であり、人の検出・意味的な動的点除去ではない。移動物が十分整合的に見える場合は
検出できないことがある。IMU・車輪の誤差は残り、長時間の遮蔽や車輪滑りを無制限には補えない。
初期化時の最初の地図作成には対応先がないため、この判定では安全性を保証できない。
閾値は設定可能な初期値。通常BAGと人工劣化BAGでの検証と、実際の屋外・群衆での検証を区別する。

## 2026-10-22 検証

`slam3d_real_20261021_205132` を私用ROSドメイン224〜229で再生し、実機ドメイン53から分離した。
正常入力の全区間は保護ON/OFFとも7,260姿勢。位置差RMS 0.0176m、保護ONでLiDAR全棄却0、
弱い区間と復帰確認による地図追加停止20スキャン。
200〜210秒に再生用の点群だけを40mずらした人工試験では、正常再生に対する235秒時点の位置差が
保護OFF 10.7455m、保護ON 0.0906m。生点群を16点に減らした試験では0.0895m。
いずれも独立した正解軌跡に対する誤差ではなく、実際の群衆の再現でもない。
劣化中の内部地図追加0を診断で確認し、別の `/Laser_map` 配信有効試験でも劣化中36,523点で一定、
復帰後42,248点まで増加した。閾値を意図的に小さくした試験で状態・共分散の復元経路も実行した。
