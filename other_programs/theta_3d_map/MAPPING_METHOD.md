# 実機BAG用の共通オフライン地図生成

共通設定は `params/offline_3d_mapping.yaml`。Launcherの `offline_3dmap` も自動で読む。CLIの明示値は優先する。同じセンサー構成で検証を積み重ねるための共通方針であり、全環境・全BAGの精度保証ではない。

既定の `frontend: auto` では `capture/recording.json` が実機録画を示す場合、FastLIO＋車輪を新しい状態から再計算して地図を作る。BAGを番号選択する通常の `offline_3dmap` だけで実行できる。過去の実行状態を引き継がず、元BAG・既存地図は上書きしない。記録LIOとの比較は `--frontend recorded`、録画モード情報のない古い実機BAGには `--frontend recompute` を使う。`--lio-bag` 指定時はその再計算結果を使う。

## 記録済みFastLIOが壊れている場合

生のLiDAR・IMU・車輪からFastLIOを再計算して、その結果を後処理へ渡せる。実機と異なるローカルROSドメインを使い、元BAGは変更しない。生センサーの時刻を保持し、デバッグログも別ディレクトリへ保存する。

```bash
source ~/sirius_jazzy_ws/bash/bash_alias2.sh
recompute_3d_lio  # BAGを番号選択。空いている新しい保存先を自動作成
offline_3dmap <元BAG> --lio-bag <表示された再計算BAG> -o <新しい地図保存先>
```

車輪融合ONが既定。FastLIOへ融合済みであることを保存するので、後処理で車輪を再び独立因子として重ねない。`--wheel off` と `--point-time legacy` は原因を切り分ける比較用。普段は既定値を使う。

今回の実機BAGでは、収録済みLIOの広がりは約1m四方。一方、新規起動した修正版による全区間再計算は、車輪OFFでも約19.4×13.9m、ONでは約20.4×13.9mになった。さらに旧時刻処理・車輪OFFで最初の220秒だけ再計算しても約17.5×14.1mの移動が出た。したがって、点時刻や車輪の有無だけで元の破綻を説明できない。収録時の内部地図・推定状態・初期化、旧バイナリ／起動設定の差が候補だが、当時の実行情報が足りず断定できない。原点の異なる座標値自体を誤差とはみなさない。

旧出力 `offline_3d_recomputed_fusion` は収束していたが、床の二重化が残っていた。収束を地図の合格基準として扱わない。Z方向の再検証と修正版の結果は `offline_3d_general_v2/VALIDATION.md`、飛び検出と反復上限2000を加えた最新結果は `offline_3d_general_v3/VALIDATION.md` に記録する。

## 入力・融合

- `/Odometry` があれば実際に読み、FastLIOの軌跡を初期軌跡・deskew・隣接拘束へ利用する。従来は記録されていても後処理で使っていなかった。
- FastLIOの `body` はIMU座標。車体との取付変換を適用する。LIOと車輪odomの原点は異なってよい。初期静止時のIMU姿勢と加速度が整合すれば、最初の同期姿勢で3D回転・並進を合わせる。この剛体変換は相対的な坂の形状を変えない。不整合・未確認ならyawのみを合わせ、地図の絶対的な上下方向を検証済みと扱わない。
- 校正はBAG内 `/tf_static` を優先する。解決できなければ収録時YAMLを使い、車体―IMUの設定もなければ停止する。今回の実機BAGでは従来の既定IMU高0.3mに対しTFは0.65mだった。
- 古い色付き点群が `time` を失っていても、同時刻・同座標系の生点群と全XYZ・点順が一致した場合だけ復元する。
- 点時刻はheaderに対する**符号付きの秒**。今回の実機は約−49ms〜＋1ms、周期は約50msだった。負値を絶対値化したり0へ丸めたりしない。
- 隣接ICPの実測した面合わせを残す。LIOが妥当でもICPをLIO姿勢で置き換えない。LIOは幾何が観測できない部分空間だけを補う。これにより、小さな高さ・傾き誤差の蓄積を点群で修正できる。LIO使用時は同じIMUの相対姿勢を重ねない。
- 隣接だけでなく、2/4/6/8キーフレーム先・距離0.7〜4.5mの重なる点群も照合する。単一の隣接ICPと1本の再訪辺だけに傾き補正を依存させない。壁・床の境界で局所PCA法線が混ざる問題を避けるため、RANSACで検証した面の法線を使用する。
- 共有する局所平面と3D姿勢を同時に補正する。壁と床、薄い壁の反対側は別の面として扱う。面はそれぞれ傾き・位置を自由に持ち、全域の床を水平固定しない。観測点の平均・共分散から平均二乗の点対面距離を計算する。[BALMの論文・公式実装](https://github.com/hku-mars/BALM)の面共有の考え方を参考にした独自の明示的平面ランドマーク実装であり、BALMの解析的ソルバの移植ではない。
- 同じ生スキャンの一つの観測平面が複数ボクセルに跨る場合、その対応も保存する。局所パッチだけが曲がった軌跡に追従する問題を抑える。再訪の局所パッチ拘束も残す。共通の線しかない対応、法線が一致しない対応、同一スキャン内の異なる平面を結合する対応は採用しない。平坦面・一定勾配だけでなく、平坦な踊り場と坂の接続・曲面も回帰試験の対象とする。
- 共有面補正の前後を同じキーフレーム・再訪ペアで検証する。床の重なりが悪化、または比較可能なペアが大きく減った場合、候補姿勢は診断用に保存し、地図には採用しない。
- LIOと車輪の移動量が継続的に大きく異なる場合、車輪＋IMUを初期軌跡に使い、点群でどちらが整合するか区間ごとに検査する。今回の記録LIOは約1m四方に留まる一方、車輪は約22m×15mに広がっており、LIOを無条件に優先する試験は地図が悪化した。
- 車輪は平面内の移動と車体Z軸回転だけを拘束する。高さ・roll・pitchをゼロ固定しない。LiDARで弱い方向は車輪を残し、幾何の裏付けがある方向で不一致なら車輪の重みを下げる。不一致だけで滑りと断定しない。
- 新しい録画では実行中FastLIOの車輪融合設定も `capture/fastlio_runtime.json` へ保存する。実行時情報を優先し、なければ収録YAMLの `wheel.enabled` を使って二重計上を避ける。どちらも実態と違う場合は `--lio-wheel-fusion already-fused` / `independent` を明示する。過去のBAGに設定がなければ起動状態までは復元できない。
- LIOの共分散には保守的なノイズ下限を使う。車輪・LIO間の完全な交差共分散を推定する密結合フィルタではない。
- ループは逆方向ICP、点群誤差、観測可能性を検査する。候補不採用後も別候補を試し、ノードごとの試行回数には上限を置く。
- LIOがなければ車輪＋IMU＋ICP。LIOの座標系変更・大きなジャンプ・リセットは停止して知らせる。

LiDARと車輪が同時に信頼できない長区間を、これらのセンサーだけで完全に補正できるとは限らない。

## 動的点の除去

再清掃の `clean_3dmap --all-scans` は高頻度の初期軌跡へ最適化補正を反映し、
全生スキャン（最適化軌跡の時刻範囲内、点時刻でdeskew）をDUFOMapの証拠に使う。
既存の削除マスクを維持して保持点をさらに選別する。保持XYZ/RGB・軌跡は変更しない。
使用スキャン数と時刻範囲外の除外数を保存する。通常生成のキーフレーム方式とは区別する。

共通設定の既定は **著者公開DUFOMap 1.1.1**（`mapping_dynamic.py`）。deskew済みの全キーフレームと最適化後LiDAR姿勢から、周辺も観測された自由空間voxelを構築し、最後に元地図を分類する。解像度0.1m・表面余裕0.2m・姿勢余裕2 voxelをBAG共通に使う。未観測・遮蔽だけでは除去しない。出力は元点群の部分集合で、保持XYZ/RGBと軌跡を変更しない。最初から動かない物体を意味クラスだけで除去する処理ではない。

v9からDUFOMap後に独自の孤立輪郭仕上げを追加。小さい群であることに加え、削除済み動体近傍で、時間を空けた再観測が乏しい場合だけ対象にする。これには推定が含まれ、DUFOMapの自由空間で証明された点だけを消す方式とは区別する。`--no-dynamic-fragments` で追加処理を無効化できる。追加対象は `dynamic_fragments.ply` とオレンジの `/offline_map/fragment_points` に分離する。詳細の共通閾値・検証範囲は `DYNAMIC_REMOVAL.md`。

以下は比較用に残す **v7方式（`--dynamic-method visibility`）** の説明：

最適化後、点群を各観測の距離画像へ投影し直す。ある時点の観測で対象点の奥まで見えていれば、その空間はその時点で空だったとみなし自由空間の票を付ける（観測時刻の前後は問わない）。手前の物体は遮蔽、光線のない場所は未観測として扱う。

細い角度ビン、距離・姿勢誤差の余裕幅、複数の矛盾票を用いる。除去は「自由空間票が2以上」かつ「自由空間票が直接観測票の2倍超、または立ち去り型（最終の直接観測より後の自由空間票が2以上で、直接観測エピソードが2以下）」のときだけ行う。静止したまま最後まで面として観測され続けた物体は残す。2026-10-17: 実機の動的障害物・人物残像対策として、自由空間票を「対象点の観測時刻の近傍」に限定する旧制限を撤廃し（去った物や後から周回した視点の「透けて見える」証拠を使う。DUFOMap等の「いつか空として観測された領域」の考え方）、閾値は `--dynamic-min-votes` / `--dynamic-free-hit-ratio` / `--dynamic-hit-cluster-max` で管理する。

このv7方式は簡易可視性フィルタで、DynabloxのTSDF・物体追跡、ERASORの全アルゴリズムの実装ではない。両方式とも姿勢誤差・ガラス・細い構造物等による誤判定や、空として観測されなかった物体の残存はあり得る。文献比較・v8の検証範囲は [DYNAMIC_REMOVAL.md](DYNAMIC_REMOVAL.md) を参照。

出力：

- `map_3d.ply` / `map_3d_colored.ply`：除去後、同じXYZ。
- `map_3d_unfiltered.ply` / `map_3d_colored_unfiltered.ply`：除去前。壁の二重化を除去で隠していないか確認する。
- `dynamic_candidates.ply`：除去候補。動的物体の正解ラベルではない。`view_3dmap` が `/offline_map/removed_points` に赤色で別配信する。
- `report.json`：使用した軌跡・重み・停止理由・点時刻復元・除去点数。
- `resolved_calibration.yaml`：TFから解決した校正。`calibration.yaml` は元の収録時YAML。

## 色付けのZずれ

現在は `theta_colorization.yaml` を共通の固定外部校正・可視性方針として使い、元画像がある場合は
`color_source: auto` で形状処理後に再着色する。公称TFは勝手に見た目へ合わせず、測定済みの
6自由度が得られた場合だけ明示的な `camera_in_lidar` として指定する。
密な地図＋生動体の遮蔽・局所平面による床の保護・高頻度の撮影姿勢・複数画像の信頼度付き中央値を使い、
保持XYZは変えない。既存地図は `recolor_3dmap` で再処理可能。詳細は `COLOR_CALIBRATION.md`。
距離信頼度の減衰は共通設定 `color_distance_power`（既定2）で指定する。
`fusion_weighted_median: true` は候補選択に加え色の最終統合にも信頼度を使う。
これは相対重みであり、校正済み確率や投影位置補正とは区別する。
オフラインでは `color_rotation_scale_deg_s`（既定5）に応じた旋回速度の重みも使う。
撮影姿勢から計算する信頼度係数であり、画像の時刻や地図の姿勢を動かす補正ではない。

軌跡と画像投影の校正は別の問題。すでに付いたRGBを合成するだけでは誤投影は直らない。

```bash
source /opt/ros/jazzy/setup.bash
python3 ~/sirius_jazzy_ws/other_programs/theta_3d_map/theta_alignment_diagnostics.py \
  ~/rosbag2_data/<BAG名> --output ~/rosbag2_data/<BAG名>/theta_alignment_check
```

画像へLiDARの奥行き境界を重ね、カメラ高±15cm・pitch±3度を比較する。候補は校正へ自動適用しない。

今回のBAGではTF上のTHETA高はLiDARから+0.285m。5場面の候補が揃わず、一定のZ補正値は特定できなかった。平均候補−2.5cm・pitch−2度も画像エッジ誤差の改善は約1.4%のみで、校正結果として使えない。複数距離・高さの対象を静止観測し、光学中心、pitch/roll、レンズ校正、映像遅延を分けて確認する。画像は記録済みなので校正後に再色付けできる。

## 参照した一次資料・採用範囲

- [FAST-LIO2（2021）](https://arxiv.org/html/2107.06829v1)：IV章の状態推定と点ごとの時刻による歪み補正を確認。今回のPython deskewは記録された軌跡の補間であり、論文の完全なIMU逆伝播実装ではない。
- [LIO-SAM（2020）](https://arxiv.org/html/2007.00258v3)：III-C〜Eの相対姿勢因子・再訪因子・地図再配置を参考にする。GTSAM/iSAM2やIMU事前積分の新規実装ではない。
- [Dynablox（2023）](https://arxiv.org/html/2304.10049v2)：IV-C/Dの保守的自由空間推定、ドリフトによる静的点誤判定への注意を参考にする。
- [ERASOR（2021）](https://arxiv.org/pdf/2103.04316)：III章のスキャン／地図の観測差、地面保持を確認。現実装はR-POD/SRTではない。
- [GenZ-LIO（2026）](https://arxiv.org/html/2603.16273v1)：V章の点対平面／点対点の併用と不確かさの重みを確認。このハイブリッド推定器への置換は未実施。法線が不確かな環境への拡張候補。

## 検証

同じ共通設定を複数BAGで使い、静的な壁・床の保持、動的除去、再訪、縮退、坂道、停止・旋回を確認する。実機に真値がなければ絶対精度やcm単位の改善を断定しない。最適化の収束だけでも正しい地図の証明にならない。未収束は警告付きの保存として扱う。共通設定の反復上限は2000で、収束すればその前に停止する。

初期静止区間ではIMUの姿勢から予測する重力方向と加速度に約4.6度の差もあった。取付回転・加速度バイアス・AHRSの基準・座標規約の点検対象であり、FastLIO破綻の直接原因と断定しない。取付・時間校正はロボットごとに一度検証する項目で、BAGごとの見た目合わせでは補正しない。

`test_offline_3d_mapping.py` / `test_mapping_fusion.py` は符号付き点時刻、XYZ対応の拒否、座標系、LIO利用、IMU・融合済み車輪の二重計上防止、縮退、遮蔽・未観測・静止中の動的除去を検証する。

追加した回帰試験は、LIOの高さ・pitchが床の実測を上書きしないこと、共有面補正が実際の坂の高さを消さないこと、収束フラグと独立に20cmの二重床を検出できることを確認する。`report.json` の `floor_overlap_quality` は、静止区間の大量の成功ペアで走行中の誤差が隠れないよう、移動した観測位置で評価する。近傍XY点の差を床の傾きで補正した高さ差であり、真値に対する絶対誤差ではない。

床点のペア内95%値をさらにペア間で95%集計して5cmを超える場合、収束済みでも完了表示を「保存完了・要確認」とし、`validation_status: needs_review` を保存する。再訪床面が観測できない場合も精度確認済みとはしない。比較用の `--no-covisibility` / `--no-planar-normals` / `--no-surface-refinement` は通常操作では不要。

最適化後の軌跡は `trajectory_jump_quality` でも検査する。連続キーフレーム間の速度が物理上限（既定2.0m/s、`--max-trajectory-speed`）またはロバスト統計（中央値2倍・中央絶対偏差の15倍の大きい方、最低0.8m/s）を超える場合は要確認とする。正当な加減速（例: 1.25→1.73m/sの実測加速）は検出せず、破綻した旧実行（m/s桁の飛び）を検出することを回帰試験で確認している。床の残差と同様、収束フラグとは独立の検査である。

## ロボット校正とBAGごとの調整を区別する

`sensor_consistency` は、車輪・ジャイロとも静止している最初の30秒内で、IMU quaternionの予測重力と加速度方向を照合する。20サンプル以上で2度を超えて不一致なら、絶対姿勢の基準には使わず、保存結果にも要確認を表示する。回転励起の固有値も記録する。yawだけの走行から、LiDAR/IMUの全取付回転・バイアス・時刻差を校正済みとは判断しない。

実機センサーの取付変換・IMUバイアス・時刻差は、実測してロボットの設定として固定し、以降のBAGにも使う項目。同じロボットの各BAGの壁や床を見て値を変える運用にはしない。シミュではモデルの取付値とセンサーデータを使う。両者で融合・面合わせ・精度検査のアルゴリズムと設定は共通だが、異なるセンサーの校正値まで同一にはしない。

今回の実機BAGは初期静止時の重力方向に約4.65度の不一致があり、回転励起もほぼ1軸だった。取付回転、AHRSの基準、加速度バイアスのどれが誤っているか、このBAGだけで一意には決められない。見た目から補正値を自動投入しない。校正データには、静止区間に加え、LiDARとIMUを同じ剛体のまま複数軸で動かした観測が必要になる。

校正対象の整理は [LI-Init（IROS 2022）の公式実装](https://github.com/hku-mars/LiDAR_IMU_Init)も参照。同手法は取付変換・時刻差・重力・IMUバイアスを扱い、十分な運動励起を確認して初期化する。今回追加したのは整合性と励起不足の検出であり、LI-Init本体や自動的な全パラメータ校正を実装済みとはしない。

通常の地図生成では床の全域水平固定をしない。今回ユーザーが明示した「同じ平坦な屋内床に近づけたい」という条件には、`offline_3dmap --known-single-floor`（新規生成）または `refine_3d_map.py --known-single-floor`（既存地図の再構築）で対応する。両者は同じ補正・採否検査を使う。CLIでの明示指定を必須とし、共通YAMLによる常時有効化、BAG名による自動適用や屋外への既定適用はしない。

このモードは各スキャンの床面を計測し、最初の床面を共通参照にして高さと傾きの姿勢補正を滑らかに最適化する。元の姿勢グラフの辺の接続を補正の平滑化に使うが、保存されていない元の計測因子を再最適化したとはしない。点そのものを床平面へ投影しない。5スキャンごとに1スキャンを学習から除き（両端の観測は拘束）、床の残差・元の対応を固定した壁の再訪誤差・軌跡飛びを検査してから採用する。実際の坂や複数階を含むデータにはこの単一床仮定を適用しない。

採用後は床法線をZ軸、参照床をZ=0とする剛体変換で地図座標を定義する。IMUの取付校正を変更する処理ではない。スキャンと軌跡から点群を再融合し、生スキャンによる動的除去・色投影をやり直すため、旧マスクを流用しない。旧2D地図やウェイポイントの座標をそのまま使えるとはしない。絶対精度の真値がないため、残差の改善と実環境に対する絶対精度は区別する。既定の要確認基準も維持する。
