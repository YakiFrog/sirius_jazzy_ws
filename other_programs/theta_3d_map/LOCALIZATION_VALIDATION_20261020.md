# 実機3D自己位置推定の追加検証（2026-10-20）

## 実施結果

NUCのROS domain 53に反映。手押し試験はユーザーの指定で後日実施する。
本日の実機評価は静止状態であり、走行中の精度を保証する結果ではない。

### IMUの200Hz設定

地図生成BAG `slam3d_real_20261016_204610` の `/imu` は平均19.968Hz、
自己位置推定BAG `localization3d_real_20261020_165243` も19.961Hzだった。
`polling_interval: 5` はPC側のシリアル読み取り間隔であり、デバイス出力周波数ではなかった。
追加した生パケット診断でも、加速度・角速度・姿勢はすべて約20Hzだった。

`params/wt905.yaml` に `output_rate_hz: 200` を追加し、読み取り間隔を1msとした。
ドライバは起動後に設定ロック解除と出力レート変更を送り、ROMへの保存命令は送らない。
`output_rate_hz: 0` は出力レートを変更しない指定。以前の20Hzに戻す場合は明示的に20を指定する。
指定できる値は0/20/50/100/200で、適用は起動時。

最終静止BAGの `/imu` は平均199.648Hz、ヘッダー間隔最大9.302ms、時刻の逆転・重複は0回。
1スキャン内のIMUは通常10個になった。シリアル受信由来の間隔のばらつきがあるため、
間隔中央値の逆数をセンサー周波数として扱わない。デバイスの取得時刻との絶対同期は未校正。
過去の20Hz BAGを200Hz相当に水増しする処理はしていない。

### FastLIO内部の診断

自己位置推定用の `lio3d_loc` で `performance_diagnostics_enabled` を有効化し、
`/fastlio/diagnostics` に1秒ごとのJSONを配信する。通常の地図生成モードでは既定で無効。

- LiDAR受信・キュー投入・取り出し・初期化・出力の各件数
- IMU受信間隔、スキャンあたりのIMU数、同期待ち回数
- 点群前処理、キュー待ち、IMU処理、EKF、地図更新、点群配信の時間
- 同一スキャンの受信からオドメトリ／点群出力までの時間
- 現在・最大キュー長、最古データの滞留時間

時間計測はsteady clockを使い、入力点群の実体と対応付ける。対応不明のスキャンに
ゼロ遅延を割り当てない。初期化中・IMU区間が空・出力成功を分けて集計する。
診断は推定の周期、センサー値、ノイズ設定、品質判定を変更しない。

### TFプロセスの分離

`theta_3d_localization.launch.py` は既定で `localization_tf_node` を別プロセスとして起動する。
地図照合ノードは `/map_localizer/correction` に採用した補正だけを配信し、重複TFを出さない。

- `map -> sirius3/odom` は最新の採用補正を保持し、現在時刻で20Hz配信。
- ロボットの運動を表すLIO側のTF・Odometryの時刻は変更しない。
- 補正の計測時刻は `/map_localizer/correction` に残す。
- 初回照合成功前はTFを配信せず、`/localization_ready=false`。
- Odometryが0.3秒、採用した補正が3秒を超えて古い場合はTFを停止する。
  計測時刻と受信後の経過時間の両方を確認する。
- `/map_localizer/tf_status` に準備状態・停止理由・元データの年齢を記録する。
  TFバッファには過去のTFが残るため、利用側もreadyと時刻を確認する。

初期の「10Hz、最新Odometryと同じ時刻」の方式では0.1秒前の参照に失敗したため、
補正TFを現在時刻で保持する方式に変更した。補正元の鮮度判定は維持している。

2026-10-20 21:41:58 JSTに保存した45秒測定（最初の5秒を集計から除外）:

| 項目 | 結果 |
|---|---|
| IMU | 199.623Hz |
| FastLIO Odometry | 19.805Hz、受信時の計測時刻からの遅れP95 16.60ms |
| map→odom TF | 20.000Hz、配信間隔P95 50.33ms、最大50.85ms |
| map→base参照 | 最新・0.1秒前・0.2秒前・0.3秒前が各800/800回成功 |
| 地図照合 | 80回採用、7回棄却 |

別の最終60秒BAGでは、照合補正が3秒更新されず、鮮度判定によりTFが一度停止・復帰した。
TF間隔の最大は149.88ms（通常P95 50.15ms）。照合不成立時まで一定周期を保証するものではない。
品質の棄却条件は緩めていない。静止中のLIOのZ変動幅は3.39mm、地図照合後のZ変動幅は82.2mm。
この差も後日の走行評価対象とする。

### 傾き補正の再評価

実機の補正は従来のroll −0.4560°、pitch +1.2778°を維持した。
FastLIOには生点群とLiDAR–IMU外部校正を与え、Leveled点群を二重に補正しない。
最終BAGの3組の生／補正後点群を記録された静的TFで比較し、XYZの最大差は0.971µmだった。

古い自己位置推定BAGを、補正あり／なし×車輪融合あり／なしの4条件で再処理した。
全条件5790姿勢、60個の局所床面を同じ乱数シードで評価した。ROS domain 220/221で実施し、
実機domain 53へ再生データを送っていない。

床が平らという仮定に基づく局所平面の比較であり、外部の正解軌跡ではない。
以前の再処理で得た「補正後P95 0.264m」という改善量は今回安定して再現していない。
傾きだけで解決済み、または完全な6DoF外部校正ができたとは判断しない。
この結果を根拠に追加の固定傾きや加速度バイアスを実機へ加えていない。
参照地図v15の形状も変更していない。
