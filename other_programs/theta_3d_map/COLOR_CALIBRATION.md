# THETA–LiDARの固定校正と色のにじみ対策

## 校正値と色付け処理を分ける

LiDARが見える床でも、位置の異なるカメラからは物体に隠れている場合がある。
座標を画像へ投影するだけでは、その床に前景物体の色が付く。
外部校正が正しくても生じるため、取り付け高さをBAGごとにずらして対処しない。

共通設定は `src/sirius/sirius_navigation/config/theta_colorization.yaml`。
ライブの `theta_colorize_cloud_node` とオフラインの再着色が同じ投影・可視性関数を使う。
`camera_in_lidar: null` は固定TFを使う指定。今回の記録TFは `[0,0,0.285] m`、回転0。
ユーザー確認では取り付け値は概算で、正確には未計測（2026-10-17）。
したがって実測済み・外部校正完了として扱わない。
今回、見た目に合わせたZ/Pitchオフセットの推定・適用は行っていない。

実測/標的校正が得られたら、共通ファイルの次の欄へ一度設定する：

```yaml
# 例の値は現在の公称TF。実測値を入力すること。
camera_in_lidar:
  xyz_m: [0.0, 0.0, 0.285]
  rpy_degrees: [0.0, 0.0, 0.0]
```

これは **LiDAR座標におけるカメラ光学原点の姿勢**（LiDAR←Camera）。
ROSのX前・Y左・Z上、RPYは右手系 `Rz(yaw) Ry(pitch) Rx(roll)`。
着色時には逆変換を使い、設定があれば公称TFより優先する。
3D色付けでは、BEV用 `theta_calibration*.yaml` の `camera_position/rpy_degrees` を編集しても
取り付けTFの代わりにはならない。焦点・歪み・前後レンズ回転は従来の内部校正ファイルで管理する。
THETAの前後レンズの光学中心差はこの共通原点近似に残る。

## 共通の処理

1. 固定外部変換でLiDAR点をカメラ座標へ変換する。
2. カメラ視点の距離バッファで、前景より奥にある点の着色を拒否する。
3. オフラインは密な静的地図と、その時刻の生LiDAR点群の両方を遮蔽物として使う。
   地図から人物を消しても、撮影時には人物が画像を遮っているため、生点群を使う。
4. 隣接画素を確認すると斜めに見た床・壁まで拒否しやすい。
   信頼できる前景側の局所平面と同じ面にある場合だけ可視へ戻す。
   法線は半径20cm・最大30近傍の共分散から判定し、線状/非平面の近傍や生動体には適用しない。
5. 画像輪郭のすぐ近くを避け、微小な校正誤差で反対側の色を拾いにくくする。
6. オフラインは近く・レンズ正面寄りの信頼できる最大5観測を保持し、信頼度付きRGB中央値を使う。
   画像間隔は共通設定の0.5秒以上。未確定の点は形状を保持して灰色にする。

画像に見えない床を、周りの物体色で埋める処理は行わない。
出力XYZ・点数・軌跡・残像除去のマスクは変更しない。

## 距離に応じた色観測の信頼度

共通設定 `theta_colorization.yaml` の `color_distance_power` で距離減衰を指定する。
観測重みは `cos(光軸との角度)^2 / max(距離[m], 1)^power`（角度項の下限は従来の0.1）。
統計的に校正された確率ではなく、複数画像の色を統合する相対的な信頼度。
既定power=2では同じ角度の2m対10mの観測重みは25対1。
power=4では625対1となる。0なら距離による減衰を無効化する。有効範囲0〜8。
`max_color_range_m` は色を取得する距離の上限で、信頼度の減衰とは別。

以前もpower=2の固定重みで最大5観測を選んでいたが、最終統合は単純中央値だったため、
近い1観測より遠い複数観測の色が採用される場合があった。
現在の共通設定 `fusion_weighted_median: true` は最終的な各RGB中央値にも信頼度を使う。
falseは従来方式。均等重みなら偶数観測の平均を含め従来の中央値と一致する。
古い設定ファイルに新しい項目がない場合はpower=2・単純中央値へフォールバックする。

遠い画像しかない点は、その観測から色を得る。距離減衰で点を削除したり、RGBを暗くしたりはしない。
単一画像を使うライブ配信では距離重みのみを変えてもRGBは変わらず、複数画像を統合する
オフライン再着色で効果がある。設定変更後は `recolor_3dmap` で別出力へ再着色する。
校正由来の投影ずれを直接補正するものではなく、遠方の誤った観測の影響を抑える対策。

## 旋回中の画像の信頼度

オフライン再着色では共通設定 `color_rotation_scale_deg_s`（既定5度/秒）を使用。
撮影時刻の前後50msの最適化補正済み姿勢から3軸の回転速度の大きさを求め、
色観測の信頼度に `1 / (1 + (回転速度 / 設定値)^2)` を掛ける。
5度/秒で重み1/2、18度/秒で約1/14。候補選択と信頼度付き中央値の両方へ反映する。
位置・姿勢・撮影時刻は変更しない。停止した観測はほぼ従来の重みを保つ。
軌跡端では範囲内の片側差分を使い、姿勢が欠落する場合はその画像の重みを0にする。
設定0で無効。新項目のない旧設定も0として再現性を維持する。ライブ配信には適用しない。

`color_image_motion.npz` に画像ごとの時刻・回転速度・係数を保存する。
取得遅延の確定値ではなく、遅延に敏感な旋回画像の影響を抑える信頼度モデル。
不確定の−0.3秒補正は適用しない。旋回中の画像しかない点については誤色が残り得る。

## 時刻

ライブは最も近い時刻の画像を選び、既定では古い最新画像への無制限フォールバックをしない。
`fixed_frame`（既定`sirius3/odom`）の時系列TFがあれば、点群時刻から撮影時刻へ運動補償する。
補償できない場合は40ms以内に限定する。対応画像がなければ元のXYZ/ring/timeを保持して灰色で配信する。

オフラインは最適化前軌跡と生成時の高頻度LIOまたは車輪/IMU軌跡を照合し、
最適化のSE(3)補正を高頻度軌跡へ補間して撮影位置を求める。
全キーフレームで初期軌跡の再現一致を検査する。真値は使わず、時刻範囲外へ外挿しない。
今回の実機は7,658 LIO姿勢を使い、再現行列の最大残差は約1.8e-14。

`image_time_offset_s` は画像headerに加える**実測の取得時刻補正**。既定0。
HDMI/USBの露光遅延を、このBAGから推測して固定値にしたわけではない。
今後のキャプチャheaderはJPEGエンコード前に取得するが、真のハードウェア露光時刻とは区別する。

## 使用方法

```bash
source ~/sirius_jazzy_ws/bash/bash_alias2.sh
recolor_3dmap  # 生成済み地図を番号選択。別ディレクトリに保存
# 直接指定する場合
recolor_3dmap /path/to/map -o /path/to/recolored_map
```

新しい `offline_3dmap` は `color_source: auto` が既定。
元のTHETA JPEGと生LiDARがあれば、形状処理の最後に同じ処理を実行する。
元のRGBは `map_3d_colored_recorded.ply` に保存し、最終 `map_3d_colored.ply` を置き換える。
`--color-source recorded` は従来RGBのみ、`--color-source images` は元画像必須。
元画像が存在しないBAGのRGBを後から正しく再投影することはできない。

内部校正は収録時スナップショットを優先し、無ければ実機/シミュ用の共通ファイルを使う。
更新した内部校正を古いBAGへ適用するときは `--calibration`（通常生成は`--theta-calibration`）で明示する。
固定外部校正/可視性方針は共通ファイルを使用し、`--colorization-config` で明示変更も可能。
収録時は `capture/theta_colorization.yaml` に共通ファイルのスナップショットも保存する。
これは起動中のノードの実設定を問い合わせた記録とは区別する。

保存するもの：

- `colorization_policy.yaml` / `theta_calibration_used.yaml`: 使用した校正・方針
- `color_observations.npz`: 各保持点の採用観測数（0の点は未確定）
- `report.json` の `colorization`: 外部変換の出所・画像数・遮蔽数・未確定数・実装ハッシュ

## 今回の検証

実機 `slam3d_real_20261016_204610/offline_3d_general_v10_color`。
v9と全417,511点のXYZ、通常地図、軌跡CSV、残像除去マスク・赤/橙の対象PLYが一致。
618画像を採用し337,873点へ着色、79,638点は未確定の灰色。
324,578点は複数画像から色を採用した。

色付け画像の選択618枚を別途再現し、それらに含まれない7枚で検査した。
現在の校正で可視と判定され、新地図で2観測以上ある同じ256,178点サンプルに対し、
画像RGBとのチャンネル平均絶対差の中央値は **24.33→10.67 /255**。
7枚それぞれで中央値が改善。`color_validation.json` に詳細。
これは**同じ公称校正に条件付けた画像整合性**で、真の外部校正誤差や全点の色正解率ではない。

## 残る物理的な確認

### エレベータ指定座標の観測追跡（2026-10-17）

ユーザー指定の `offline_map` XY=(17.76, 8.22) をv12で確認。
代表の白い点(17.7724, 8.2335, 1.1738)mはRGB=(184,188,189)。
`trace_color_observations.py SOURCE --xy 17.76 8.22 --output NEW_DIR` で、
元と同じ全シーン遮蔽・法線・画像選択から色を再現し、採用した上位観測を追跡できる。
`elevator_color_trace/report.json` は全416,417点のRGB再現一致を確認した記録。

白い代表点の上位5観測は開始約175.6〜178.2秒、距離2.70〜2.93m、
隣接画像の姿勢差から見た旋回速度は約17.2〜18.2度/秒。
元画像の投影先は黒い扉に隣接する白い壁にあり、近距離のため高い重みで採用されていた。
旋回が弱い別の5画像（約0.03〜0.8度/秒、同じ点まで2.89〜3.56m）では、
同じ点の公称投影先はRGB約0〜2の黒い画素。`slow_view_check.json` に保存した。
この追加検査は画素色だけで、各観測の遮蔽・採用可否は再判定していない。
撮影姿勢を時刻−0.1〜−0.4秒で試すと5画像すべてで暗い画素へ移る。
−0.3秒候補の代表比較は `time_check_0278.png`、試行値は `time_check.json`。
これは1か所の画素色の検査で、正しい対応点・遅延−0.3秒を確定したものではない。
一定の取り付け角度差でも似た変化が起こるため、停止時と逆向き旋回を含む検証が必要。
候補をロボット校正・現在地図へ自動適用しない。

従来の `color_comparison.png` / `confidence_comparison.png` はx∈[-7,10]mの範囲に限られ、
この指定箇所は表示範囲外だった。局所確認は `elevator_color_trace/roi_current.png` を参照。
全点の数値検査と、表示範囲を限定した図の確認を区別する。

### 黒白の境界に沿う横方向の混色（2026-10-17）

ユーザー確認では、黒いエレベータ壁に隣の白壁の色が混ざるのは境界沿いの細い帯。
候補は公称TFの微小なyaw/横位置誤差、映像取得の時刻差、魚眼レンズ校正・左右レンズ光学中心近似。
現在の画像境界除外は1pxで、それを超える投影誤差は避けきれない。
境界除外を広げるだけでは未確定の灰色が増え、投影校正そのものの修正にはならない。

`theta_alignment_diagnostics.py BAG --map MAP --output NEW_DIR` で横方向yawと時刻差を診断できる。
高頻度軌跡へ最適化補正を反映し、点時刻deskewと撮影時刻への運動補償を行って、
LiDARの奥行き境界と画像エッジの距離を比較する。候補を校正や地図へ自動適用しない。
`--yaw-range-deg 4 --time-range-s .4` は探索範囲の指定で、校正値の指定ではない。

今回の `theta_horizontal_check_wide/` は9場面。集計の候補yaw +1.33度・時刻差−0.30秒で、
エッジ距離の平均2.255→1.449px。ただしこれは探索に使った画像での適合値。
場面別yawは0〜2度、時刻差は−0.40〜+0.15秒で揃わず、2場面は探索境界。
ほぼ静止した場面でもyaw +1.33度の候補が出るため、取り付け角度は確認対象だが、
画像の模様と奥行き境界は同一ではなく、エレベータ領域の正解対応点もない。
この結果を測定済みの外部校正・取得遅延と表現しない。公称TF・時刻補正・v10のRGBは維持。

固定配置でも、6自由度の実測値、レンズ内部校正、取得時刻の誤差は別に確認する必要がある。
複数距離・向きのチェッカーボード等から3D–2D対応を取り、固定外部変換として一度校正する。
例えば [ILCCの著者実装](https://github.com/mfxox/ILCC) / [原論文](https://arxiv.org/abs/1708.05514) は
パノラマカメラとLiDARの標的校正を扱う。今回その校正器自体を組み込んだとはしない。
本体/取り付け具がカメラに写り込むがLiDARでは測れない場所、光沢・ガラス、動体の未観測、
VLP16の疎な光線やスキャン中の動きには遮蔽判定の限界が残る。
